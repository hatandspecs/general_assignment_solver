1. Pre-Assignments (optional, before the first solve)

Load a pre-assignment JSON file, or edit the Pre_Assignments table directly in Grist (open it from the page list on the left) — either way, each row becomes an hour-range constraint (min/max) on one project/person/month in Bounds, guiding the solver before it ever runs. Optional — skip straight to step 2 if you don't have any this month.

2. Run Planning — solve, review, and tweak

Solves with the current Pre-Assignments merged in, and writes the result into the Allocation table — open it from the page list on the left to see the actual solved hours for every project/person this month. This is not one-and-done: hand-edit any row's hours_assigned there, check its locked box, and click Run Planning again — that cell stays pinned exactly as you set it while everything else re-optimizes around it. Repeat as many times as you like. Nothing is committed (no change to Bounds or Pre_Assignments) until step 3.

3. Export Work Assignments — commit

Re-solves once more, then permanently merges this month's Pre-Assignments into Bounds (the hour-range constraints) and clears the Pre_Assignments inbox — Allocation (the actual solved hours) is refreshed the same way step 2 does, so the two always agree. Do this once you're happy with the plan from step 2; it also produces this month's work-assignment sheet, the one that goes out to the team.
